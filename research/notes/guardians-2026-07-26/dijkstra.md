# DIJKSTRA SEAT — canonical surface, minimal state space

## 1. CORE JUDGMENT

The repo has exactly one profound object, and it is already built: **the observation multiset as sufficient statistic, sealed in `src/packet.rs`**. The chain — pairwise log-ratio observations form a free commutative monoid; under Huber weights no smaller mergeable sufficient statistic exists; `fuse` canonicalizes the multiset so partition-order equivalence is bitwise `==` rather than 1e-9-close; dedup by content address makes the packet set a G-Set CRDT — is a genuine correctness-by-construction result, ~300 lines, pinned by `tests/program_equivalence.rs`, with the CRDT claim stated at exactly the right strength (the 07-09 red team's double-counting catch is honored in the module doc, and evidence-disjointness is explicitly deferred to the provenance layer). This is book-quality. It is the thing other repos should consume.

The problem is that the canonical object is **almost unreachable from the surfaces consumers actually meet**. Packets are emitted by exactly one niche path (`cardinal judge --consortium --packets-out`); `fuse` has no CLI verb; `sort`/`rerank` — the verbs with real callers — emit traces and JSON responses but never packets; `cardinald` speaks a fourth format (`judgement-run.v1`). A consuming repo today faces four overlapping serialization boundaries for one capability: `RerankRequest`, `MultiRerankRequest`, `judgement-run.v1`, and `JudgmentPacket`, plus `ComparisonTrace` JSONL as a fifth evidence carrier. The kernel is minimal; the doorway is not.

The conceptual state space is growing at the perimeter while the core is stable. The CLI has **21 verbs**; `judge` alone carries 8 mode flags (`--spin`, `--sweep`, `--orbit`, `--draws`, `--wordings`, `--consortium`, `--show-prompt`, `--packets-out`) whose product space is mostly unspecified — nothing in the types forbids `--spin --orbit --consortium` together. Conceptually, spin, wordings, and two-sidedness are *projections of the one general object already built* — the Z₂³ orbit — yet they live as four flags and three modules. `slate`, `anp`, `distinguish`, `weigh`, `canonize`, `calibrate`, `elaborate`, `explain` are each individually defensible research instruments, but jointly they present the *largest* possible expression of one capability to a first-time consumer, when the canonical-tools goal demands the smallest.

**What is the canonical artifact?** Verdict: the **packet format is the canonical interchange atom** (the only piece with a proven algebra), and the **CLI is the canonical execution surface** — the crate cannot be, until the git-only `seriate` dependency is resolved (README concedes no crates.io publication; a git dependency is a private arrangement, not a canonical tool). `cardinald` is not canonical: it is a localhost deployment for one consumer, and it leaks that consumer's schema (`owner_scope`, `lens`, ClickHouse landing) into the kernel repo. `judgement-run.v1` is sound as an *execution record* — provenance and replay are a genuinely different concern from evidence — but it is the provenance layer, not a rival atom.

**Invalid states still representable at the public boundary** (all verified in source):

- `MultiRerankGateSpec.unit` / `.op` are `String` (src/rerank/types.rs:344-354) — stringly-typed with runtime validation; an enum deletes the invalid region for free.
- A `JudgmentPacket` with NaN `log_ratio` has a valid content id and fuses without error; `fuse` silently clamps nonpositive/NaN precision via `.max(f64::MIN_POSITIVE)` (src/packet.rs:283) — a success-shaped fallback inside the one module whose whole point is refusing bad evidence.
- `JudgmentPacket.created` sits inside the canonical-byte identity (src/packet.rs:157): byte-identical evidence with a different timestamp is a distinct packet, so the G-Set idempotency guarantee is weaker than it looks — re-sealing the same evidence double-counts. Either move `created` out of the identity preimage or document that identity is deliberately evidence+stamp.
- `NormalizedJudgementRunRequest` has all-`pub` fields (src/judgement_run.rs:62-69), so the "validated" newtype is constructible without `validate()` — parse-don't-validate with the enforcement deleted.
- `RerankStopReason` is a field a consumer can ignore: `items` is readable without ever seeing `budget_exhausted`, and the README concedes all synthetic runs stop there. Correct-by-construction would make certification status unmissable in the result type (a `Certified`/`Uncertified` split, or the sort surface refusing bare access).

## 2. STRONGEST OBJECTION to the current trajectory

Each work wave adds a verb, a module, a report struct, and an options struct at the perimeter (slate, anp, distinguish, axis waves 07-24→25), while the consumable core — `sort_texts` + packet/fuse — has been finished and stable for weeks. The state space a would-be consumer must trust grows superlinearly (verbs × flags × formats), and the four-format doorway means the repo's own best theorem (bitwise fusion) is not what any consumer would encounter. The standing red-team finding says distribution is the binding constraint and the protocol has one speaker; from this seat the corollary is sharper: **the surface is optimized for the one speaker's research loop, and every additional research verb makes the canonical-tool story less true, not more.** Churn risk is not in the kernel — it is the perimeter accreting until the kernel is illegible from outside.

## 3. MOVES (≤3, sized, each with its loser condition)

**Move 1 — Partition the surface by decree, not by code (small; docs only).** Declare in README/AGENTS: the canonical consumable is `sort_texts`/`sort_documents` + CLI `sort` and `judge` + the packet format; everything else (`weigh`, `slate`, `anp`, `distinguish`, `canonize`, `explain`, `calibrate`, eval verbs) is research-grade, stability-unpromised. Zero deletion, zero churn — a labeled boundary. *Loser if*: real consumers need multi-attribute gates on day one, in which case `multi_rerank` belongs inside the line and the partition was drawn wrong.

**Move 2 — Close the packet loop (small-medium; plumbing, the algebra exists).** Give `sort`/`rerank` a `--packets-out` that seals each run's observation multiset as a packet, and add a `cardinal fuse <packets...>` verb over the existing `fuse()`. Then the repo's one theorem becomes its one product: any two parties (or one party across runs/models/days) exchange sealed evidence and get bitwise-identical posteriors. This is the single highest-leverage canonicalization available — it converts the mathematical result into the tool. *Loser if*: no second fusing party ever materializes and single-operator cross-run fusion is served well enough by the SQLite cache — then this is cathedral polish and Hamming's seat wins the point.

**Move 3 — Make the sealed module reject instead of clamp (small; one module + one versioned decision).** In packet construction/fusion: reject non-finite `log_ratio` and nonpositive/non-finite `precision` (new `PacketError` variant, not a clamp), seal `NormalizedJudgementRunRequest` fields, enum-ify gate `unit`/`op`, and decide `created`'s identity status explicitly. Bounded, behavior-preserving for all valid inputs. *Loser if*: existing committed evidence packs contain packets the stricter rules invalidate — then it must land as a `v2` domain tag or be dropped; never silently reinterpret sealed v1 artifacts.

## 4. WHAT IS SOUND / MUST NOT BE CHURNED

- **`src/packet.rs` in its entirety** — the monoid argument, canonical byte encoding (length-prefixed strings, f64 bit patterns, no JSON in the identity path), the precisely-scoped CRDT claim, entity-hash tamper refusal. Do not "improve" this module except via Move 3's explicit rejections; its restraint is its correctness.
- **The solver contract** (`rating_engine.rs`: IRLS + Huber, gauge pinning, content-addressed `EngineSpec` replay binding) and the trace-to-spec binding in `MultiRerankMeta` — warm-start observations forcing replay to fail closed is exactly right.
- **`sort.rs` as the model of a convenience surface**: the middle-boundary remap with its full justifying comment (src/rerank/sort.rs:514-522), counterbalance-on-by-default, probes as peers with weight ±1, empty-input refusal, single-item trivial case with honest all-zero accounting. This is what the other 20 verbs should aspire to.
- **The documentation posture**: MODEL.md's non-goals and known-failure-modes, README's mixed-evidence admissions (10/12/20, budget-efficiency unproven). Denominators everywhere. This register must never be churned toward marketing.
- **The `judgement-run.v1` record itself** (as provenance, distinct from evidence) — the concern separation is correct even though the daemon around it is premature.
